## Как продолжить

**Окружение:** Node 24 (только встроенные модули для tools/*), любой современный браузер. Зависимостей нет, сборки нет — vanilla JS (ES5-стиль IIFE, как в PinRefBoard).

**Команды:** `node tools/dev-server.mjs` → http://127.0.0.1:8940/ (статика + POST /api/dev-save пишет data/db.js без токена; работает только на localhost при DEV_MODE в js/config.js); `node tools/test-parse.mjs` — тесты парсера ссылок (19 кейсов).

**Точки входа:** `index.html` → `js/app.js` (приложение: стейт, рендер, DnD, модалки) → `js/api.js` (GitHub Contents API: токен, sha-guard), `js/videos.js` (парсеры ссылок + резолверы метаданных), `data/db.js` (данные — глобал `window.__PVB_DATA`, коммитится сайтом).

### Решения и допущения
- Вход по вставке токена, а не OAuth: CORS GitHub закрыт для device flow из браузера (проверено WebSearch), а серверный прокси противоречит идее «только Pages»; подход как у Prose.io.
- Данные — `data/db.js` (JS-глобал), а не JSON: конвенция PinRefBoard, работает и на file://; парсинг удалённой версии — срез префикса присваивания.
- Репозиторий уже был git-init'нут пользователем (README, .gitattributes `* text=auto`); коммит сделал локально, push не выполнял (привычка пользователя из PinRefBoard — пушить самому, токены не трогать).
- В тесте парсера найден и исправлен баг регулярки `watch\?.*?[?&]v=` (съедала единственный `?` у простых ссылок) → `watch\?(?:[^#]*[?&])?v=`; заодно появился постоянный тест-файл.
- Клик-меню колонок/доски: добавлен `stopPropagation`, иначе документный обработчик «клик мимо меню» закрывал меню мгновенно.
- IAB-грабли: Playwright-клики по локатору во встроенном браузере зависают (rAF не тикает → проверка стабильности вечна) — тестирование через координатные клики и evaluate-клики.

### Открытые вопросы и риски
- noembed.com — сторонний бесплатный сервис: если ляжет, YouTube-названия берёт YT IFrame API, остальные провайдеры — только ручной ввод.
- Rutube oEmbed: CORS на живом сайте не проверен (в моём окружении тест был через IAB; при неудаче — fallback noembed/вручную). VK и Dzen автоматически не резолвятся.
- Токен в localStorage уязвим к XSS; на статическом сайте без сторонних скриптов риск низкий, документировано в README.
- GitHub Pages кэширует до ~10 минут — после коммита контент обновляется с задержкой; владельцу данные всегда отдаются свежие через Contents API.
- Токену нужен именно `Contents: Read and write` на этот репозиторий — иначе 403 с внятной подсказкой в модалке входа.
