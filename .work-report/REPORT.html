Задача 1 — Сервис PinVideoBoard: галерея + канбан + редактирование с сайта — 2026-11-22

Агент: ZCode (GLM)

Запрос пользователя

Мне надо создать сервис для последующего размещения на GitHub Pages (репозиторий D:\GitHub\PinVideoBoard). Сервис в котором я смогу авторизовавшись добавлять в виде канбана или Pinterest досок видео с ютуба или любого другого видео-хостинга. Я хочу чтобы при этом в карточку видео которую я создаю в сервисе автоматически подтягивалось превью видео и его название. Я также хочу чтобы можно было переносить из одной канбан колонки в другую. Чтобы каждая колонка имела свой визуальный цветовой вид. В открытой части я хочу выводить данные канбан плитки (с видео) в видео сетки подобно тому, как это сделано на Pinterest. Должна быть фильтрация и т.п. При этом в открытой части должно считываться авторизован ли я. Если авторизован, то могу добавлять, редактировать или удалять плитки, создавать новые доски (плейлисты) и т.п. Также хотелось бы открывать видео в модальном окне при необходимости меняя размер данного окна с видео (условно 50% от ширины, 30% от ширины окна или же на весь экран).

Что сделано

  • Спроектирован и согласован план: статический vanilla-JS сайт в стиле соседнего PinRefBoard; данные — data/db.js (глобал window.__PVB_DATA); запись через GitHub Contents API с sha-guard; вход — вставка GitHub-токена (Device Flow OAuth невозможен: на github.com/login/device/code нет CORS — подтверждено поиском, источники в плане).
  • Реализованы: публичная masonry-сетка (CSS columns) с чипами провайдера/колонки/доски, тегами и цветной полосой колонки; фильтры (вкладки досок с каунтами, поиск по /, провайдер, тег, сортировка, сброс); канбан-вид с цветными колонками (палитра 8 цветов), HTML5 drag & drop между колонками и внутри колонки + резервный перенос через меню карточки (мобильные); управление колонками (добавить/переименовать/цвет/удалить с переносом плиток) и досками (создать «+ доска»/переименовать/удалить); модальный плеер с пресетами 30% / 50% / во весь экран, навигацией ←/→, «На хостинге ↗», Esc; вход владельцем по токену с проверкой owner и сохранением в localStorage; sha-guard конфликта с выбором «перезаписать / загрузить удалённые».
  • Автопревью и названия: YouTube — i.ytimg.com (fallback-цепочка maxres→hq→mq без сети), название noembed → скрытый YT IFrame API (getVideoData().title) → ручной ввод; Vimeo — официальный oEmbed (CORS, даёт длительность); Rutube — oEmbed; остальное — noembed → ручной ввод; прямые mp4/webm — <video>.
  • DEV_MODE: на localhost сохранение идёт в data/db.js через tools/dev-server.mjs (POST /api/dev-save) без токена — на Pages флаг инертен.
  • Протестировано в браузере по полному сценарию (см. «Что проверено» выше), после тестов data/db.js возвращён к стартовому чистому состоянию.
  • Локальный коммит 16f3af3 на main (10 файлов, без push).

Изменённые файлы

  • index.html — страница: шапка, сетка, канбан, модалки (плеер, плитка, колонка, доска, вход, confirm)
  • css/style.css — тёмная тема в конвенциях PinRefBoard, masonry, канбан, DnD-индикаторы, плеер
  • js/config.js — owner Mmitekk, repo, ветка, DEV_MODE
  • js/api.js — GitHub Contents API: вход/валидация токена, чтение/запись файла, sha-guard
  • js/videos.js — парсеры ссылок (YT/Vimeo/Rutube/VK/direct/other) + резолверы + embed-URL
  • js/app.js — приложение: стейт, рендер, фильтры, DnD, меню, модалки, auth-UI
  • data/db.js — стартовые данные: доска «Основная» с 3 цветными колонками
  • tools/dev-server.mjs — локальный сервер 127.0.0.1:8940 + /api/dev-save
  • tools/test-parse.mjs — тест парсера ссылок (19 кейсов)
  • README.md — возможности, публикация, создание токена, локальная разработка, схема данных

Как проверить

  • node tools/test-parse.mjs — 19/19 ok
  • node tools/dev-server.mjs → http://127.0.0.1:8940/ — «+ Добавить видео» → вставить YouTube-ссылку → «Определить» → название/превью получены → «Сохранить» → карточка в сетке; вкладка канбана → перетаскивание мышью и через «⋮»; плеер 30/50/⤢; после перезагрузки данные на месте (dev-save)
  • На живом сайте после публикации: «Войти» → fine-grained токен (Contents: Read and write на PinVideoBoard) → правки коммитятся в репозиторий

Решения и допущения

  • Вход по вставке токена, а не OAuth: CORS GitHub закрыт для device flow из браузера (проверено WebSearch), а серверный прокси противоречит идее «только Pages»; подход как у Prose.io.
  • Данные — data/db.js (JS-глобал), а не JSON: конвенция PinRefBoard, работает и на file://; парсинг удалённой версии — срез префикса присваивания.
  • Репозиторий уже был git-init'нут пользователем (README, .gitattributes * text=auto); коммит сделал локально, push не выполнял (привычка пользователя из PinRefBoard — пушить самому, токены не трогать).
  • В тесте парсера найден и исправлен баг регулярки watch\?.*?[?&]v= (съедала единственный ? у простых ссылок) → watch\?(?:[^#]*[?&])?v=; заодно появился постоянный тест-файл.
  • Клик-меню колонок/доски: добавлен stopPropagation, иначе документный обработчик «клик мимо меню» закрывал меню мгновенно.
  • IAB-грабли: Playwright-клики по локатору во встроенном браузере зависают (rAF не тикает → проверка стабильности вечна) — тестирование через координатные клики и evaluate-клики.

Открытые вопросы и риски

  • noembed.com — сторонний бесплатный сервис: если ляжет, YouTube-названия берёт YT IFrame API, остальные провайдеры — только ручной ввод.
  • Rutube oEmbed: CORS на живом сайте не проверен (в моём окружении тест был через IAB; при неудаче — fallback noembed/вручную). VK и Dzen автоматически не резолвятся.
  • Токен в localStorage уязвим к XSS; на статическом сайте без сторонних скриптов риск низкий, документировано в README.
  • GitHub Pages кэширует до ~10 минут — после коммита контент обновляется с задержкой; владельцу данные всегда отдаются свежие через Contents API.
  • Токену нужен именно Contents: Read and write на этот репозиторий — иначе 403 с внятной подсказкой в модалке входа.

Ответ пользователю

Что внутри: публичная Pinterest-сетка с фильтрами (доски, поиск, провайдер, теги, сортировка), канбан-вид с цветными колонками и настоящим drag & drop, модальный плеер 30% / 50% / на весь экран с навигацией ←/→; при вставке ссылки плитка сама подтягивает превью и название (YouTube, Vimeo — включая длительность; Rutube/VK — с ручным вводом как запаской); вход владельца — вставка GitHub fine-grained токена, правки коммитятся в репозиторий с защитой от конфликтов. Проверено в браузере: добавление/перенос/удаление, перезагрузка данных, мобильный вид, ошибок нет; тест парсера ссылок 19/19. Осталось за вами: привязать remote и запушить (git remote add origin https://github.com/Mmitekk/PinVideoBoard.git && git push -u origin main), включить Pages (main / root), затем на сайте «Войти» с токеном с правом Contents: Read and write — и редактировать прямо с сайта. Задача 2 — Монохромный стиль дизайна — 2026-11-22

Агент: ZCode (GLM)

Запрос пользователя

А можем дизайн сделать в монохромном стиле?

Что сделано

  • Весь интерфейсный хром переведён в монохром: --accent #4a9eff → #d9d9d9 (светло-серый), кнопки «Добавить видео»/primary — инвертированные (светлый фон, тёмный текст), ссылки/теги/фокус-ринг/drop-индикатор/тосты (кроме сигнальной ошибки) — серые.
  • Превью (галерея, канбан, превью в редакторе) — grayscale(1) contrast(1.04) по умолчанию, цвет проявляется при наведении на карточку и по переключателю — точный паттерн PinRefBoard (body.color .card img { filter:none }).
  • Кнопка «Показать цвет» (иконка-полукруг, как у PinRefBoard) в шапке: класс body.color + сохранение в localStorage pvb-color.
  • Цвета колонок в моно-режиме переводятся в различимые оттенки серого по яркости (hexToGray, luminance с клампом 100–200) прямо при рендере: полосы карточек, точки/тинты шапок колонок, чипы колонок, точки в меню переноса. В цветном режиме — исходные цвета. Палитра в редакторе колонок остаётся цветной (выбор цвета), видео в плеере — всегда цветное.
  • Кэш-бастинг поднят до ?v=2 (css, app.js).

Изменённые файлы

  • css/style.css — моно-переменные, инвертированные primary/add кнопки, grayscale-правила превью, body.color, серые тосты/теги/индикатор, .icon-btn.active
  • index.html — кнопка #color-toggle в шапке, версии ?v=2
  • js/app.js — COLOR_KEY, hexToGray/monoColor (luminance→серый), state.color, applyColorMode, обработчик переключателя, monoColor во всех местах вывода --c/цветов меню
  • data/db.js — сброшен к стартовым данным (тестовые плитки убраны)

Как проверить

  • node tools/dev-server.mjs → http://127.0.0.1:8940/ — по умолчанию монохром; кнопка-полукруг в шапке включает цвет (сохраняется после перезагрузки); в канбане колонки различимы оттенками серого; наведение на карточку проявляет цвет превью.

Решения и допущения

  • Выбран паттерн «моно по умолчанию + показать цвет» (как у PinRefBoard), а не полное обесцвечивание: цвет колонок — исходное требование пользователя из ТЗ, переключатель сохраняет обе возможности.
  • Серый из цвета — по яркости (0.299R+0.587G+0.114B) с клампом 100–200: разные исходные цвета дают разные различимые оттенки серого.
  • Сигнальные цвета (ошибка в тосте/валидации, зелёный авторизации, палитра-пикер) оставлены цветными сознательно.

Открытые вопросы и риски

  • Пороговых жалоб не ожидается; если захочется цвет «по умолчанию» — одна строка в boot (state.color = true).

Ответ пользователю

Но цвет не потерялся: в шапке появилась кнопка «Показать цвет» (иконка-полукруг) — она возвращает цветные превью и цветные колонки; выбор запоминается, при наведении на карточку цвет проявляется и без переключателя. Видео в плеере и палитра в редакторе колонок всегда цветные — это функциональные элементы. Проверено в браузере в обоих режимах, сохранение после перезагрузки работает; закоммичено (0670a1d), db.js возвращён к чистому состоянию.
